## Mirror and fork state

- A shallow local source checkout is available at `upstream/bun`, detached at the earlier snapshot `05a0ec93a614b69389ed2593463f6b08e697391e`. It does not match the newer `bun-upstream-main` revision in `source-lock.json` (`e57d89ba63a7504957faa2ccc8f416ce2fb15453`). Git reported no changes and no declared Git submodules for the earlier snapshot. This establishes source availability, not a successful build or a downstream fork. See `docs/receipts/bun-upstream-checkout.json` for its hashes.
- The pinned tree already contains `src/jsc/bindings/CookieMap.cpp` and `src/dotenv/env_loader.rs`. Audit those implementations and the historical Aphrody fork before porting cookie or environment functionality; do not duplicate an upstream API merely because it exists in BunOS.
- The earlier checkout's `rust-toolchain.toml` requests `nightly-2026-09-15` and additional targets/components; check the current locked revision separately. The host's active Rust version alone does not establish build readiness. Windows build dependencies and the upstream Rust/C++ LTO pipeline remain to be qualified.

- `yolo-rs/bun` is a direct fork of `oven-sh/bun`, fast-forward synchronized on 2026-11-04 to `e57d89ba63a7504957faa2ccc8f416ce2fb15453` (upstream commit timestamp 20:04:03Z). Keep it at upstream `main`.
- `aphrody-labs/bun` is an archived fork of the same upstream, with a divergent history. Its latest commit observed was `7c57ac563e12c35be817697c4b5488b0fd64cc09` (2026-10-28). GitHub compare reports a large shared-history divergence; that count is not a count of Aphrody-authored commits.
- The archived fork README describes BunOS-specific commands (`bun mcp`, `bun lsp`, `bun agent-plugin`) and integration APIs. These must be ported as `yolo-bun` adapters, not copied into the exact upstream mirror or described as upstream features.

The word **canary** in this repository means the current `oven-sh/bun` development branch, pinned by commit. Use a versioned stable release for reproducible image builds unless the image profile explicitly opts into a canary lane.
